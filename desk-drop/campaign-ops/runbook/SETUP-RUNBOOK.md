# Setup runbook

Numbered steps, in order. **[FOUNDER LOGIN: x]** marks a step only you can do, in your own account. **[SPEND]** marks a step that costs money: stop there, decide, and give your written yes first. Nothing in this folder has been signed up for, sent, bought or published.

Software cost of this system: **$0 a month** on top of the Google Workspace seat you already have (plan, tools table). The only paid fallbacks are named where they apply.

## A. Once, before the first office signs (weeks 1 to 3)

1. **Your computer.** Python 3 with `pip install openpyxl segno pillow`; Node 18 or newer with Playwright (`npm install` and `npx playwright install chromium` in `desk-drop-identity/`, as its README says); poppler (`pdftoppm`) for the QR check; LibreOffice is optional (only for `tools/recalc.py`). In `campaign-ops/_work/node/`, run `npm install` once (QR decoding for the checks). All free.
2. **The tracker file.** It is already built: `tracker/campaign-tracker.xlsx` (blank, every formula in place), at the **six-month size**: rows for about six drops, 16 campaigns and 160 office rows with half again as headroom, 53,397 formula cells (review round 1 cut it from 87,013, so Google Sheets has less to recalculate on a phone; review round 2 added the roster and direct-ship columns). To rebuild it after a change to the tools: `python3 tools/build_tracker.py`; for a longer run, `python3 tools/build_tracker.py --size full` ("Speed and size", below). The working name is read from `desk-drop-identity/brand.json` into one cell, config!B2; it is nowhere else in the file.
3. **[FOUNDER LOGIN: Google]** Open sheets.google.com, start a blank spreadsheet, File > Import > Upload `campaign-tracker.xlsx` > **Replace spreadsheet**. Name the file `campaign tracker` (never the company name in a file name). File > Settings: Locale **United States**, Time zone **America/New_York** (form timestamps and the window depend on it).
4. **Check the import (3 minutes).** The dashboard tab must show 0 on every check line and no `#NAME?` or `#REF!` anywhere. Type a Friday into `drops!B2`: it must be refused (a validation warning) and `date_check` must read REFUSED. Clear it. **Speed, on your phone:** open the tracker in the Google Sheets app, type a number into an empty `hours` cell and time how long the grey cells take to settle. Over 3 seconds: tell the operations builder, or rebuild smaller ("Speed and size") before drop day, because drop-day logging happens on the phone. This could not be tested in Google Sheets from the build environment (no login): the file was recalculated and checked in LibreOffice only. Unverified, founder to confirm; if any cell shows an error, tell the operations builder the cell address.
5. **Fill config** (config tab, column B): `founder_name`, `founder_phone`, `founder_email`, `postal_address`, `receiving_address` (a street address that takes parcels; a PO box cannot), `short_link_domain` (step 10), `survey_privacy_url` (the website's survey notice page), `bank_details` (after the business bank account exists: legal pack file 04). Leave `company_name` as it is unless you rename (README, "Rename").
6. **Sharing.** Share the tracker with no one (legal pack file 13, D6). A backup person gets printed route sheets, not the file.
7. **[FOUNDER LOGIN: Google]** **Website intake into the tracker.** Recommended: bind the website's script to this file so website sign-ups land in the tracker's `office_intake` and `brand_intake` tabs directly. In the tracker: Extensions > Apps Script, paste `website/apps-script/Code.gs`, run `setup()` once, then deploy as `website/SETUP.md` section 3 says. The tabs already carry the exact CONTRACTS 6.3 headers in row 1. Read in Code.gs: `setup()` inserts a tab only when it is missing, and `ensureHeader_` only compares a header that is already there, never rewrites it; `nextRow_` finds the next row from column A. It was not run here (no login): look at row 1 of both tabs afterwards. Alternative: keep the website's own sheet and paste its rows into these tabs.
8. **[FOUNDER LOGIN: Google]** **The founder-side intake forms** (for offices and brands before the website is public, or during a call): build them from `forms/office-intake-form.md` and `forms/brand-qualification-form.md`, link each to the tracker, delete the placeholder tab and rename Google's new tab `office_form` / `brand_form`. **Settings > Responses > "Restrict to users in [your domain] and its trusted organizations": OFF** (a Workspace form is closed to other companies by default: support.google.com/a/users/answer/9303071, opened 2026-10-24). Then open each form's link in a private or incognito window: it must open with no sign-in.
9. **[FOUNDER LOGIN: Google]** **The survey and sign-up masters:** `forms/survey-form.md`, Parts 1 and 3. Do not link the masters to any sheet. **"Restrict to users in [your domain]": OFF on both**, and check it again on every campaign's copy (Part 2, step 8: open an office's link signed out of Google; if it asks for a sign-in, no employee can answer). Use them live only once the attorney hour has cleared legal pack file 13.
10. **[FOUNDER LOGIN: Short.io, and your DNS]** **The link tool:** `links/QR-AND-LINKS.md`, "Once". Free plan. If Short.io asks for a card or no longer has a free plan, stop: the fallback is Bitly Core at $10 a month billed yearly ($120, bitly.com/pages/pricing, opened 2026-10-24) **[SPEND]**, or the no-count fallback on the website's domain. **Domain age:** the QR links open on phones that may sit on an office's Wi-Fi, and some corporate firewalls block domains registered in the last 32 days (Palo Alto Networks' "Newly-Registered Domains" category, as cited by `desk-drop-outreach/sending/sending-setup.md`, source S17, opened 2026-10-24 by the outreach workstream; not re-opened here). `go.[DOMAIN]` is a subdomain, so it carries the age of `[DOMAIN]`: the domain must be registered by **Mon 2026-12-07** for the Tue 2027-01-12 drop. The outreach plan buys it Mon 2026-10-26, which clears this; a different domain for the links would need the same 32 days. **The domain must be name-neutral** (the outreach plan's default): a link domain that carries the working name would put the name in every printed QR link and strand the cards after a rename (links/QR-AND-LINKS.md, rules).
11. **Hours from day one.** Log every work session on the tracker's `hours` tab (date, drop or blank, one of the seven activities, decimal hours). Discovery time has a blank drop_id. Toggl is optional: its free plan tracks time, but its CSV export is a paid feature (Starter $9 per license a month, per financial-model/HANDOFF.md, opened 2026-10-23) **[SPEND]**, so the tab is the default.
12. **[FOUNDER LOGIN: Wave]** Optional. Invoices are made by `tools/make_invoice.py` from the tracker, so nothing is typed twice. If your accountant wants a bookkeeping ledger (legal pack file 09), record each invoice and payment in Wave Starter (free; waveapps.com/pricing, opened 2026-10-24). Do not turn on Wave's card payments; bank transfer is the default (card fee 2.9% plus $0.60, same page).

12a. **[FOUNDER LOGIN: Dropbox Sign] Signatures.** The legal pack sends both agreements "through the free e-signature tool the operations workstream sets up". Choice: **offices** sign by replying "I agree" to the email that carries the PDF (participation agreement section 10 allows it), so they use no signature quota. **Brands** sign through Dropbox Sign's free plan: 3 signature requests every 30 days, a bundle sent together counts as one, and a signed PDF comes with an audit trail (help.dropbox.com/plans/dropbox-sign-free-plan, opened 2026-10-24). Send the agreement and its Part 1 as one bundle. Campaign zero needs 2 brand requests. A standard month with up to 6 new brands needs more: the brand can then sign the PDF and email it back (brand agreement section 14: "Electronic signatures count"), or you buy Essentials at $15 a month, or $10.05 a month billed yearly (sign.dropbox.com pricing page, opened 2026-10-24) **[SPEND]**, only with your written yes. File each signed PDF in Drive under the campaign_id, and log `agreement_signed_date` on the campaigns tab.

## B. When offices sign and brands say yes (weeks 3 to 7)

13. **Offices.** When the outreach workstream exports `desk-drop-outreach/handoff/signed_offices.csv` (published header-only on 2026-10-24, with a SAMPLE copy beside it that `tests/test_e_handoff.py` pastes into a test tracker): on the `in_signed_offices` tab, File > Import > Upload > **Replace current sheet**. On `offices`, type each new `office_id`; everything grey fills in by column name. Then geocode the address once: `python3 _shared/geocode.py "<street address>"` from `desk-drop/` (run one at a time) and type `lat`, `lon` and `building_id`. Fill `front_desk_fallback_ok` (ask the owner; in a direct-ship drop an office without it gets its cartons from you by hand), `delivery_point_note` and `building_coi_status`. If the offices tab's `checks` asks about a coworking space or the cluster boundary, confirm it with the office and type Y in `eligibility_confirmed`, or set the office's status to left.
14. **Brands.** On `brands`, type `brand_id` and paste the brand's `submitted_at` from `brand_intake` (or `brand_intake_founder`) into `intake_key` (paste, do not type: the column is plain text). Check `qualified`: nothing ships until it reads Y (the campaign's `ship_release` holds on "qualification"). Type the billing fields (legal name, billing address, billing email) from the agreement's Part 1 **before the first invoice**: `make_invoice.py` refuses without them. When E's `paid_brands.csv` arrives, import it on `in_paid_brands`; the dashboard lists any brand in it that is missing from `brands`.
15. **Drops.** On `drops`, use the financial model's drop IDs (DRP-001 for campaign zero, Tue 2027-01-12; financial-model/HANDOFF.md section 1). Pick dates with `python3 tools/opscal.py next <date>`.
16. **Each campaign:** a row on `campaigns` at the brand's yes, then the invoice: a row on `invoices`, then `python3 tools/make_invoice.py tracker.xlsx INV-001 out/`. Send it with the agreement (legal pack file 10) and the certificate request (file 11) **[FOUNDER LOGIN: email]**. Log `paid_date` the day the money is in the business account; the ship date is released by the tracker, not by you.
17. **[FOUNDER LOGIN: Google Calendar]** For each drop: `python3 tools/make_calendar.py tracker.xlsx DRP-001 out/` and import `sop-DRP-001.ics` (Settings > Import). The deletion reminders are in it.

## Speed and size

The tracker is built at one of two sizes (`tools/trackerdef.py`, `SIZES`):

| Size | Rows for | Formula cells | Use |
| --- | --- | --- | --- |
| `six-months` (shipped) | 20 drops, 50 campaigns, 250 office rows, 800 stock movements, 1,600 link readings, 1,500 hours rows | 53,397 | to the six-month decision |
| `full` | 40 drops, 100 campaigns, 400 office rows, 1,500 stock movements, 2,000 link readings, 3,000 hours rows | 89,807 | a longer run |

Rows below a tab's last formula row are not counted anywhere, so the dashboard line "Tabs over 90% full" turns red before any tab runs out. Then: `python3 tools/build_tracker.py --size full --out new.xlsx`, import it as a new spreadsheet (step 3), and copy every tab's white and cream columns across (Edit > Paste special > Values only), then point the forms at the new file (Responses > Link to Sheets). Unverified: how fast either size recalculates in the Google Sheets phone app (step 4 times it).

## What could not be verified from here (founder to confirm)

- Speed on a phone (step 4 and "Speed and size").
- That the Google Forms setting is named, and sits, as Google's Workspace help says ("Restrict to users in [domain] and its trusted organizations", under Settings > Responses), and that turning it off lets a signed-out phone answer. The optional forms script also calls `setRequireLogin(false)`, which Google's FormApp reference marks deprecated (developers.google.com/apps-script/reference/forms/form, opened 2026-10-24); the same reference says new forms default to no login "unless a domain administrator changes the default", while the Workspace help says access is restricted by default. Trust the signed-out test, not either page.
- Google Sheets' import of this file (step 4) and of its data validation and conditional formatting.
- That Google Sheets keeps the longest formulas whole on import: `brands.e_payment_check` is 14,459 characters and `campaigns.checks` 9,156 (both recalculate in LibreOffice). Excel's documented limit is lower (8,192 characters, from memory, not re-opened here), so work in Google Sheets, not Excel; if step 4 shows an error in either column, tell the operations builder.
- That links in a Google Form's confirmation message are clickable (forms/survey-form.md, Part 2, step 3, has the fallback).
- Short.io's import column names and its DNS steps (links/QR-AND-LINKS.md).
- That the website's `setup()` keeps the tracker's existing intake tabs as they are (step 7).
- The 32-day newly-registered-domain rule (step 10): taken from the outreach workstream's source S17, not re-opened here.
- Dropbox Sign's free-plan terms on the day you sign up (step 12a): read from its help page on 2026-10-24; plans change.
