# Campaign operations and measurement

The system a campaign runs on, from the first office intake to the day-30 redemption check. It has one tracker (a Google Sheet with formulas), four Google Forms, short links and QR codes, the kit, the route sheet, invoices, the brand report, debrief notes, the SOP and the exports for the financial model. Every number in a brand report comes from a logged row or a photo, and every tool that makes a document reads the tracker, so nothing is typed twice. Contribution per founder hour for each drop and each campaign is on the dashboard the day after the drop.

Start with `runbook/SETUP-RUNBOOK.md` (numbered, with the steps that need your login marked), then `sop/SOP.md`. The SAMPLE dry runs in `dry-run/` show every document this folder makes. **Nothing here has been sent, signed up for, bought or published.** Software cost: $0 a month beyond the Google Workspace seat.

Version 1.2 · 2026-10-24 (review round 1 fixes: an office that declines at the door, open forms for outsiders, payments counted once, the rename check, the route sheet's counts; see `_review/round-1.md`). The working name sits in one place in this folder, the tracker's `company_name` cell (config!B2), seeded from `desk-drop-identity/brand.json`; every tool refuses while the two differ ("Rename", below). It is in no file, folder or link name here.

## The tracker's tabs

White cells you type; grey cells are formulas (never type over them); cream tabs are written by forms, scripts or a pasted file. The dashboard's check lines should all read 0; a line starting `info:` in a checks column is a fact, not a task.

| --- | --- | --- |

| `survey_dashboard` | (read only) responses per office for the campaign in B2, under-5 flags, what was not counted | |
| `report` | (read only) the plan's one-page layout for the campaign in B2, by formulas | |

## Commands

Download the tracker from Google Sheets first (File > Download > Microsoft Excel). Run from `campaign-ops/`.

```
python3 tools/opscal.py next 2027-02-01 4                         # valid drop days
python3 tools/make_calendar.py tracker.xlsx DRP-002 out/sop        # the drop's dated SOP and .ics
python3 tools/make_invoice.py tracker.xlsx INV-004 out/invoices    # an invoice or credit note
python3 tools/make_messages.py tracker.xlsx DRP-002 approvals out/ # drafts for one step: approvals, ship_release, t3, t1,
                                                                   #   on_my_way, placement_confirmation, day3, day5, newsletter,
                                                                   #   report, redemption
python3 tools/make_links.py tracker.xlsx DRP-002 out/links         # T-4
python3 tools/make_kit.py tracker.xlsx DRP-002 out/kit [--final]   # T-3 (--final for a real print run)
python3 tools/make_route.py tracker.xlsx DRP-002 out/route         # T-1
python3 tools/make_report.py tracker.xlsx CMP-004 out/reports --photos <photos folder> [--final]   # T+7
python3 tools/make_messages.py tracker.xlsx DRP-002 report out/ --reports out/reports              # T+7, only where a PDF exists
python3 tools/make_debrief.py tracker.xlsx DRP-002 out/debriefs    # T+7 to T+10
python3 tools/export_actuals.py tracker.xlsx exports/              # T+10, and after day 30
python3 tools/freeze_survey.py tracker.xlsx CMP-004 out/           # 12 months on, before deleting the answers
python3 tools/build_tracker.py [--size full] [--out X.xlsx]        # rebuild the blank tracker
bash tests/run_all.sh                                              # every check (about 5 minutes)
bash tests/run_all.sh --dry-runs                                   # and the three replays (about 30 minutes)
```

Exit codes: 0 done; 1 usage; 2 refused (the message says why: a bad date, a ship HOLD, a quote not word for word, a missing count, a template refusal, no report PDF, missing billing details, the name differing between the tracker and brand.json).

## Rename

The name lives in one cell here and in one file for the printed pieces, and the tools refuse to print anything while the two disagree, so a kit can never carry two names:

1. In `desk-drop-identity/brand.json`, change `BRAND_NAME` and run the identity workstream's rename step (`node render/build-brand.js`, its README). That changes the wordmark on the tent card, case label and report.
2. The same day, on the tracker's config tab, change `company_name` (config!B2). The dashboard title, the Sheets report tab, the Slack posts, route sheet, invoices and messages follow it.
3. Download the tracker and run any tool once (for example `python3 tools/make_route.py tracker.xlsx DRP-00X out/`). While the two names differ, every generator stops with "REFUSED: the name differs" (exit 2) and names both values (`tests/test_exception.py`, case 6).
4. Print new cards for the next drop. Printed cards keep the old name and link domain; the link domain is name-neutral by rule (links/QR-AND-LINKS.md), so links keep working.

No file, folder or link name here contains the name (`tests/check_folder.py`).

## Decisions waiting on you

The blocking questions, each with a recommended default, are in REPORT.md. The defaults are already built in: Short.io free for links on a name-neutral domain, Google Forms open to people outside your organization, invoices from the tracker by bank transfer, payments counted once through the outreach log, no credit for a short shipment, consented emails only in a separate sign-up form, campaign zero founder-delivered from home storage.
