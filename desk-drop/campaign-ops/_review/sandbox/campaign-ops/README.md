# Campaign operations and measurement

The system a campaign runs on, from the first office intake to the day-30 redemption check. It has one tracker (a Google Sheet with formulas), four Google Forms, short links and QR codes, the kit, the route sheet, invoices, the brand report, debrief notes, the SOP and the exports for the financial model. Every number in a brand report comes from a logged row or a photo, and every tool that makes a document reads the tracker, so nothing is typed twice. Contribution per founder hour for each drop and each campaign is on the dashboard the day after the drop.

Start with `runbook/SETUP-RUNBOOK.md` (numbered, with the steps that need your login marked), then `sop/SOP.md`. The SAMPLE dry runs in `dry-run/` show every document this folder makes. **Nothing here has been sent, signed up for, bought or published.** Software cost: $0 a month beyond the Google Workspace seat.

Version 1.1 · 2026-10-24. The working name sits in one place, the tracker's `company_name` cell (config!B2), seeded from `desk-drop-identity/brand.json`. It is in no file, folder or link name here.

## The tracker's tabs

White cells you type; grey cells are formulas (never type over them); cream tabs are written by forms, scripts or a pasted file. The dashboard's check lines should all read 0; a line starting `info:` in a checks column is a fact, not a task.

| Tab | One row per | You type |
| --- | --- | --- |
| `dashboard` | (read only) checks to fix (19 lines, including departed offices' contact details past their keep date), drops, campaigns with every rung, hours by activity, contribution before overhead | |
| `survey_dashboard` | (read only) responses per office for the campaign in B2, under-5 flags, what was not counted | |
| `report` | (read only) the plan's one-page layout for the campaign in B2, by formulas | |
| `config` | setting | `company_name` (the one place the name lives), your details, link domain, prices, rules, `office_summary_min_answers`, `contacts_keep_days_after_leaving` |
| `calendar` | holiday or blackout | nothing (built from `opscal.py`) |
| `drops` | drop (route) | id, date (refused unless valid), model, status, courier, backup |
| `campaigns` | brand per drop | terms, card text, the ship-date email as sent (date, units), survey links, report text, debrief answers, privacy dates |
| `brands` | brand | id, intake key, billing, evidence, certificate check |
| `offices` | signed office | office_id (the rest fills from the outreach file), coordinates, delivery notes, certificates, status, left date |
| `approvals` | office per campaign | asked, reply, units override. Its grey columns hold the office's whole ladder; letters run over offices that did not decline |
| `stops` | office per drop | route order, times, outcome, debrief answer |
| `inventory` | unit movement | received, rejected, delivered, topped_up, collected, returned, given, released, disposed, correction |
| `counts` | shelf count | placed, remaining day 3, remaining day 5 |
| `photos` | photo | date, file, card visible, no people or screens |
| `links` | (formulas) two per office per campaign | |
| `<campaign_id>` | survey answer | written by that campaign's Google Form |
| `scans` | link reading | baseline, mid, close, late totals |
| `redemptions` | brand report | as-of date, count |
| `issues` | deviation | what happened, what you did, when the brand and office were told |
| `hours` | work session | date, drop, campaign, activity (seven keys), hours |
| `costs` | direct cost | drop, campaign or blank (shared), kit / transport / other_direct |
| `invoices` | invoice or credit note | issued, amount, paid date (for a credit note: the refund date, or blank if taken off the balance) |
| `office_intake`, `brand_intake` | website form row | (the website's script) |
| `office_form`, `brand_form` | founder-side form answer | (Google Forms) |
| `office_intake_founder`, `brand_intake_founder` | (formulas) the founder-side answers in 6.3 columns | |
| `in_signed_offices`, `in_paid_brands` | the outreach handoff rows | (import E's CSV, replacing the sheet) |

## Commands

Download the tracker from Google Sheets first (File > Download > Microsoft Excel). Run from `campaign-ops/`.

```
python3 tools/opscal.py next 2027-02-01 4                         # valid drop days
python3 tools/make_calendar.py tracker.xlsx DRP-002 out/sop        # the drop's dated SOP and .ics
python3 tools/make_invoice.py tracker.xlsx INV-004 out/invoices    # an invoice or credit note
python3 tools/make_messages.py tracker.xlsx DRP-002 approvals out/ # drafts for one step: approvals, ship_release, t3, t1,
                                                                   #   on_my_way, placement_confirmation, day3, day5, newsletter,
                                                                   #   report, redemption
python3 tools/make_links.py tracker.xlsx DRP-002 out/links         # T-4
python3 tools/make_kit.py tracker.xlsx DRP-002 out/kit [--final]   # T-3 (--final for a real print run)
python3 tools/make_route.py tracker.xlsx DRP-002 out/route         # T-1
python3 tools/make_report.py tracker.xlsx CMP-004 out/reports --photos <photos folder> [--final]   # T+7
python3 tools/make_debrief.py tracker.xlsx DRP-002 out/debriefs    # T+7 to T+10
python3 tools/export_actuals.py tracker.xlsx exports/ --pipeline   # T+10, and after day 30
bash tests/run_all.sh                                              # every check (about 2 minutes)
bash tests/run_all.sh --dry-runs                                   # and both replays (about 30 minutes)
```

Exit codes: 0 done; 1 usage; 2 refused (the message says why: a bad date, a ship HOLD, a quote not word for word, a missing count, a template refusal).

## Rename

Change `company_name` on the tracker's config tab (one cell). Everything the tracker prints follows it, and the scripts read it from the downloaded file. The printed pieces (cards, labels, report) take the name from `desk-drop-identity/brand.json`, which the identity workstream's rename step changes; `make_report.py` and `make_kit.py` use whatever that file holds. No file, folder or link name here contains the name (`tests/check_folder.py`). A new domain is one cell, `short_link_domain`, plus new cards.

## Decisions waiting on you

The blocking questions, each with a recommended default, are in REPORT.md. The defaults are already built in: Short.io free for links, Google Forms, invoices from the tracker by bank transfer, consented emails only in a separate sign-up form, campaign zero founder-delivered from home storage.
