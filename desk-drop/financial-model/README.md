# Financial model (workstream H)

The workbook the founder opens every week for six months to see whether the business is working: contribution per founder hour on each drop, the lowest point of cumulative cash, and which gate or decision scenario the real numbers point to.

Every figure is a planning estimate from `plan.md` or the legal pack (`desk-drop-legal-pack/figures.csv`; verified fees say so on Inputs), never a forecast. The working name lives in one cell (Inputs, section 1, "Company name").

## Open it in Google Sheets (needs your Google login)

1. Go to sheets.google.com, sign in, and open a blank spreadsheet.
2. File, Import, and choose `Desk Drop financial model v1.xlsx` from your computer.
3. Pick "Replace spreadsheet", then Import. (Steps from Google's help page "Import data sets in Google Sheets", support.google.com/docs/answer/40608, opened 2026-10-24. The README tab inside the workbook gives the same route.)
4. File, Settings: set the locale to United States and the time zone to America/New_York, so dates and the as-of date read correctly.
5. Check the Dashboard: next to "Checks" it should say "all integrity and data checks pass", and the Checks tab should show 0 failing. Then a 30-second check of the one-row lookups: Scenarios!H10 should show 2 and Cash_Flow!C35 should show 13, not #REF!. Every INDEX over a single row is written INDEX(range, 1, column), the form Google documents, so this should hold. A live import was not possible from the build environment, so this check is yours (unverified, founder to confirm). If either cell shows #REF!, tell the builder: that is a blocker.

## The weekly routine

1. Hours_Log: add the week's hours (date, drop_id or blank, one of seven activity keys, hours).
2. Pipeline: paste or type outreach events.
3. After a drop: paste the actuals into Actuals_Campaigns and Actuals_DropCosts (File, Import, "Replace data starting at selected cell", with cell A4 of the tab selected). Dates must arrive as real dates and amounts as numbers: a value stored as text drops out of the cash flow and the gates, so Checks counts them ("stored as text") and the Dashboard banner turns red. The README tab, "Dates and amounts must be real dates and numbers", gives the fix. Set "Actuals in" to Y on Schedule once revenue, payments, direct costs and hours are final (by T+10, the debrief). `code_redemptions_day30` (T+30) and renewal answers can be filled in later; they move no money or hours. The Gate 3 rate stays "not yet" until every standard run dated by the review has actuals in. If Checks shows a header failure, the pasted file's columns differ from HANDOFF.md.
4. Read the Dashboard. "Cash at each stop point" shows, for each gate, what you have paid out, the brand cash received, the refunds you would owe on campaigns not yet run, and the net if you stop there.
5. Optional: type the week-end bank balance on Cash_Flow, row 30, and read the variance against the model.
6. When a quote, date or plan changes, edit Inputs or Schedule. A drop you add takes the next spare drop_id (DRP-006 onward) and may sit out of date order; that is fine, because the model reads dates, not row order. Never re-sort the Schedule rows. If you move week 1, move the gate and drop dates too (Checks flags week 1 moved on its own). The "Changed?" columns keep the plan default beside your edit. Blue cells follow another date by default (Gate 2 follows campaign zero; insurance and most startup payments follow their gate).

## Change the price in under a minute

Inputs, section 3, "Standard price per office": type a new number. On the Dashboard, "Price in force" shows it and the next row, "A standard drop at that price: contribution per founder hour", moves with it ($73.7 at $150, $90.4 at $180). "Standard runs to Gate 3" and the drop table at the bottom move too. "Its contribution per founder hour" does not, because the next drop is campaign zero at the founding rate.

To try a price without moving the model, use the Calculator tab.

## `_work/` (scripts and evidence)

| File | Purpose |
| --- | --- |
| `build_model.py` | Builds the workbook with openpyxl. Rebuilding overwrites the file, so it would erase anything typed into a copy of it. Use it only to change the structure. |
| `readme_text.py` | Text of the README tab. |
| `recalc.py` | Recalculates the workbook with LibreOffice headless and prints checks, errors and key outputs; `--csv DIR` writes the clean tables to DIR and the tab snapshots to DIR/snapshots. |
| `export_clean.py` | The clean-table exporter `recalc.py` calls. It finds each table by its header text. |
| `audit_formulas.py` | Lists every formula with a numeric literal other than 0 or 1 (result: 0 of 20,306), every function used against Google's Sheets list (38 functions, all listed), features Sheets would drop, any cell other than the one input cell that spells the company name, and any INDEX over a one-row range without an explicit row argument (result: 0; 6,027 written INDEX(range, 1, column)). Cell, conditional-format and validation formulas are all scanned. |
| `test_model.py` | 151 behaviour tests on edited copies: price, processing, storage, insurance billing, close rate, drop size, office goal, scenarios A to D, zero brands, zero standard brands, one office, 100% renewal, Friday and blackout dates, added drops, gates slipping, pasted files with extra or renamed columns, duplicate renewal answers, the decision rule after the decision date, a SAMPLE actuals run through every gate, Gate 3 with one standard run missing, part payments, budget-probe medians, hours logged outside a drop, a mailbox quote, cash at each stop point, the live README price text, Toggl import, the bank check, bad data, dates and amounts pasted as text, the trademark line, a drop added mid-sequence, scenario levers that follow the plan base, refunds at each stop point, unpriced lines, the renewal rate per brand, scenario A's roster, week 1 moved on its own and the clean CSVs. Tests tagged [R1-xx], [R2-xx] and [R3-xx] cover the fixes for review rounds 1 to 3. The deliverable is never modified; SAMPLE rows never ship. |
| `dump.py` | Prints recalculated ranges, for review. |
| `test_log.txt`, `audit_log.txt` | Output of the last test and audit runs. |
| `ref_map.json` | Where each named input and key output sits (sheet and cell), for the scripts. |
| `NOTES.md` | Working notes: plan readings checked by hand, research with dates, round-by-round findings. |
